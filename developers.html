Put a verified person behind your agent’s actions

The reference service is open for testing over plain HTTP. Issue a token, record what your agent did, and let anyone verify it.

Quickstart

Five calls, end to end

# Base URL of the reference service
BASE=https://vac-system-production.up.railway.app

# 1. Issue an L1 token for your agent (API-key level, no biometrics)
curl -s -X POST $BASE/v1/vat/issue/l1 -H 'Content-Type: application/json' \
  -d '{"developer_email":"you@example.com","agent_id":"my-agent","resources":["calendar:events"],"actions":["read"]}'
# returns { "jti": "vat_root_...", "provenance_ref": "prov_...", "compact_jwt": "eyJ..." }

# 2. Verify it (optionally require a minimum level)
curl -s "$BASE/v1/vat/verify/VAT_JTI?required=L1"

# 3. Record an action your agent took under the token
curl -s -X POST $BASE/v1/vat/record/action -H 'Content-Type: application/json' \
  -d '{"vat_jti":"VAT_JTI","action":"read","resource":"calendar:events","result":"success"}'
# returns { "recorded": true, "aar_id": "aar_...", "provenance_ref": "prov_..." }

# 4. A person rates the outcome
curl -s -X POST $BASE/v1/vat/aar/AAR_ID/feedback -H 'Content-Type: application/json' \
  -d '{"rating":"approved"}'

# 5. Read the agent's reputation (note the agent: prefix)
curl -s $BASE/v1/vat/reputation/agent:my-agent
Endpoints

The ones most integrations need

EndpointWhat it does
POST/v1/vat/issue/l1Issue an L1 root token for an agent.
GET/v1/vat/verify/{jti}Walk the chain to the root; ?required=L1|L2|L3 checks the weakest hop.
GET/v1/vat/chain/{jti}Return the chain for display.
POST/v1/vat/record/actionRecord an action and its outcome against a token.
POST/v1/vat/aar/{aar_id}/feedbackAttach a person’s rating to an action record.
GET/v1/vat/reputation/{agent_id}Execution, feedback and combined reputation for an agent.
POST/v1/vat/auth/captureBiometric verification that issues an L3 root. Used by the ceremony.

The full, current list is in the API reference (OpenAPI). Revocation and derivation are operator-controlled on the reference service.

Until a package ships, the HTTP calls above are the whole integration, and they are what the client will wrap. When it is published, this section will name the package and its version.

Handing a verification from one site to another

When a site needs a fresh human verification, it opens the VAC ceremony in a new tab. On success, VAC issues a short-lived token bound to that site’s audience and a one-time nonce, and posts it back only to the requesting site’s registered origin. No password or session token crosses sites, and the receiving site verifies the token itself.

Between VAC and Athena’s own sitesLIVE

Used today for Athena Vault grants and owner sign-in.

Third-party sitesCOMING

Not available yet. Third-party sites will follow the verified-human-root draft, so they can check that a person is behind a request without holding any biometrics.
