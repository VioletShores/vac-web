The architecture, end to end

One rail from a verified human to a sealed decision — and the operating system underneath that runs every AI task as an accountable unit of work. A working system running end-to-end; this page describes how the pieces compose.

The stack in one view

VERIFIED HUMAN (VAC — biometric root, liveness, challenge-response) │ ▼ AUTHORITY & POLICY (delegation chains · assurance floors · action classes) │ ▼ L0 PACKETS (every task: plan → execute → verify → seal) │ │ ▼ ▼ SIGNALRANK ROUTING THE CONSTELLATION (per-domain calibrated (all packets share awareness; trust picks the model) sentinels never stop running) │ │ └────────────┬──────────────────────┘ ▼ SEALED, TAMPER-EVIDENT RECEIPTS (who authorised what, under which policy, with which model, at what tier)

1 · The root — a verified person running today

Everything starts from a natural person proven live: multi-modal verification — face, hand gesture, and a spoken random challenge, bound together in real time so cloned voices and replayed video don't pass. From that root, authority is delegated in constrained chains: to colleagues, to organisations, to AI agents — each delegation scoped by action class, amount, purpose, and time. The question every AI system is now being asked — "which human approved this, and how do you know?" — is answered at the protocol layer, not in an application's logs. Experience the ceremony (two minutes, phone browser).

2 · Policy — autonomy as configuration running today

An organisation sets its position on the autonomy spectrum as policy: a minimum assurance floor (from lightweight liveness to full biometric ceremony) that every authorisation must meet, with per-action rules able to demand more — never less. Human oversight becomes a configured, enforced, evidenced property of the system rather than a procedures document. Changes apply from the next request onward, enforced server-side at verdict time. The policy engine is named for the IETF’s Common Open Policy Service (RFC 2748) and inherits its decide-once, enforce-everywhere architecture — policy-control lineage the founder deployed in carrier-grade networking long before applying it to AI authority. See the organisation surface (demonstration organisation).

3 · L0 — every task is an accountable packet

Beneath the trust layer runs Athena, an operating system whose unit of work is the L0 packet: every task — answering a question, building a feature, producing a report — travels one lifecycle: planned → researched → executed → verified → deployed → confirmed → attested → fed back. A packet carries its authority (who asked, under which policy), its budget, and its provenance, and it ends in a sealed record. The discipline this buys: nothing runs as an orphan — every piece of AI work in the system can answer for itself afterwards.

4 · The constellation — packets that never stop

Packets don't run in isolation: they form a constellation with shared awareness — a compressed "North Star" context that gives each packet knowledge of what matters system-wide. Sentinel packets are the always-running class: they watch, consolidate, and act on schedules — overnight jobs that stitch multi-source research, refresh the knowledge base, triage feedback, and scan the standards and market landscape, each one policy-classified, budget-capped, and sealed like any other work. The design intent in one line: autonomous operation with provenance — a system that can work unattended precisely because every piece of that work remains accountable to a verified human root.

5 · SignalRank — trust as measured evidence running today

Which model should do which work is not an opinion here. SignalRank maintains a per-domain trust calibration built from our own harnesses: known-answer challenges across medicine, finance, law, regulation, strategy, code and more — 11,000+ scored challenges across 32 domains, judged by a multi-family panel with rank-agreement checks, spanning the major frontier and open-source model families (Anthropic, OpenAI, Google, xAI, DeepSeek, Meta, Moonshot among them). Production routing runs on these scores.

  • No model wins everywhere — leaders differ by domain, which is the entire case for calibrated routing over single-model loyalty.
  • Measured humility — every model scores poorly on live-knowledge questions without web access; the system knows this as data, not assumption, and routes accordingly.
  • Evidence over benchmarks — vendor-published numbers enter the trust graph only when independently reproducible; the rest stay out until we can run them ourselves.

6 · Standards posture

The protocol layer is being shaped in the open: two Internet-Drafts posted to the IETF — draft-zagarella-verified-human-root (rooting agent delegation in a verified natural person) and draft-zagarella-autonomy-governor (bounded, policy-governed autonomy) — with in-person participation at IETF 126 in Vienna, where the proposed working group on agent audit records and delegation traceability is the natural home for this work. The system is designed to map to NIST 800-63-4 assurance levels, ISO/IEC liveness standards, and the human-oversight and record-keeping articles of the EU AI Act.

How one request flows, end to end

An AI proposes a consequential action → the request declares its action class → policy resolves the required assurance tier → the named human completes the ceremony at that tier → the server seals a receipt binding person, policy, tier, model, and decision → the receipt joins the audit stream any supervisor or counterparty can verify — and the packet that carried all of this feeds its outcome back into the trust graph. One rail, no gaps between "the AI acted" and "a person answerable for it said yes."
