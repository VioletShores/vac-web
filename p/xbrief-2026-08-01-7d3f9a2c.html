3Garry Tan ships GBrain — a "thin harness, fat skills" second brain

x.com/garrytan — status …833546
Ingest

Garry Tan (YC President) publicly endorses an open-source "clean harness" for personal or "company brain" AI — his team's daily driver. Ingest reads this as mainstream validation of the orchestration-as-foundation-layer thesis, with a competitive/commoditisation flag on basic harness functionality.

Our research

The repo is github.com/garrytan/gbrain (MIT). Architecture: 8-layer pipeline (signal detection → brain-first lookup → hybrid vector+BM25 search → typed-edge graph traversal → cited synthesis → auto-linking → overnight "dream cycle" dedup/contradiction pass → markdown-as-system-of-record persistence). The "thin harness, fat skills" split routes everything through one resolver file to 40+ markdown skill recipes — intelligence lives in the skills, not the runtime. Company brain adds OAuth 2.1 scope-gating over the identical BrainEngine interface; an HTTP MCP server (gbrain serve --http) lets teammates point a remote agent at the shared brain with zero local setup.

Learnings for our harness: reusable — the evidence-tagged retrieval pattern (every result carries why_it_matched + a trust hint of exists/probable/unknown) and the cost/quality search-mode bundling (conservative/balanced/tokenmax) are both directly transferable to SignalRank's routing explain-layer. Not reusable — their entity schema and dream-cycle heuristics are tuned to personal/company memory, not model routing; SignalRank would need its own cost-tracking and model-selection policy layered on top, GBrain doesn't route between LLMs at all, it's a memory substrate one harness (any harness) sits on top of.

4Jack Dorsey's Buzz — agents as signed, audited channel members

x.com/cyrilxbt — status …276833
Ingest

Ingest identified a self-hosted server bundling channels, search, git, and automation that gained 14,400 GitHub stars in days, and flagged it as validating demand for sovereign, self-hosted infrastructure (relevant to L0/VAC) — it did not name the project or author.

Our research

This is Buzz, Block/Jack Dorsey's open-source workspace (Apache 2.0, github.com/block/buzz) — a self-hosted Nostr relay (Rust/Axum + Postgres + Redis) with desktop/mobile/CLI clients. Every message, reaction, workflow step, review approval, and git event is a signed event in one log. AI agents join channels as first-class members with their own Schnorr-signed keypair (NIP-42/98) — not bot accounts with permission flags — so every agent action carries the same audit trail as a human's. A YAML workflow layer (message/reaction/schedule/webhook triggers) is wired to Claude Code, Codex, and goose via an ACP↔MCP bridge (buzz-acp); approval-gate infrastructure exists but the docs call the orchestration glue "still drying."

Rob's hard question, answered directly: what they wire that we haven't — (1) identity and audit are the same primitive: an agent's every action is a cryptographically signed event, not a log line bolted on after the fact; (2) a working, generic ACP↔MCP bridge already plumbed into three real coding agents; (3) git-branch-as-channel, so code review and team chat share one timeline. What to reuse vs build: reuse the concept, not the code — "agent as a channel member with its own persistent identity and a full audit trail" is the shape VAC already wants, but Buzz's identity is a bare keypair with no proof-of-human behind it, which is precisely VAC's gap to fill rather than a threat to our moat. The part to build ourselves, because Buzz has neither: the trust-weighted routing layer (SignalRank) and the biometric root of identity (VAC) that decides which human is accountable for which agent's signed action.
