## What this change does

In `pharma-demo.html` only:

1. **Removed** the disconnected `domains-cta` "Try the live biometric" CTA and its navigation-based hand-off (`pharmaOpenVerify`, the `vac_last_verified` localStorage mirror consumer, the `storage`/`pageshow`/`visibilitychange` listeners). That code path is superseded by (2).
2. **Copied `sealReauthGate` and the message-listener return-handling from financial-demo.html (its lines ~814–887 in the pre-change file) into pharma-demo.html as a named function of the same name**, reusing the page's existing `#verifyOverlay`/`#voFrame`/`#voClose` markup (already present in pharma-demo.html, previously wired to the old navigation-based flow). One line was dropped from the verbatim copy: `resetDemoSurface('full')`, which only exists in financial-demo to reset its dual FAST/FULL reauth-demo surface — pharma-demo has no such surface, and the function doesn't exist here, so calling it would throw. Everything else (the overlay open/close, the `vac-auth-success` message filter, the `window.__vacGateActive` guard, the reauth query-string prefill logic) is unchanged.
3. **Step 4 ("Seal") of the walkthrough now triggers `sealReauthGate` before minting** — reaching this step opens the live ceremony automatically. On pass, it mints (`mintPharmaToken`) then calls the newly-added `authorizeSeal()` (copied from financial-demo's, action `seal_decision`, resource `pharma:site:qp_release`) before showing the receipt. On cancel, the step stays put and the button offers a retry.
4. **`verification_method` in the mint body is now conditional**: `'multi_modal'` when the live ceremony completed (`window.__vacVerified` carries an email + session token), `'credential_check'` otherwise. `actions` in the minted token's scope gained `seal_decision` (needed for `authorizeSeal` to be able to authorise against it — an action absent from a token's scope is rejected by the backend regardless of identity match).
5. **Added a clearly-labelled "Skip the live check (demo only)" link** inside Step 4's detail panel. It closes any open ceremony overlay, then mints under the sample identity (`qp@pharma-demo.vac`) with `verification_method: 'credential_check'`, still calls `authorizeSeal()` (which — per (c) below — fails closed with `no_session_token` since there's no live session to authorise against), and jumps straight to the receipt.
6. **Receipt now shows a "Verification method" row and an "Action gate + audit" row** reflecting the server's real `/v1/vat/authorize` verdict verbatim — `GATED & AUDITED` only when the server says `authorized:true`; otherwise "server refused: …" or "not server-authorised" — mirroring financial-demo's honesty rule. The "Authorised by" row spells out "skipped the live check — demo only" when the skip path was used, so the skip is visible on the receipt itself, not just in the UI flow.
7. Honest-scope copy (the `fwd-note` and the footer `.posture` line) updated to describe the new default (live ceremony gates the seal) and the labelled demo-only bypass.

## Binding resolutions applied

- **(a)** `sealReauthGate` is a verbatim-as-possible copy of financial-demo.html's function, kept as a separately named function in pharma-demo.html rather than factored into a shared module. **This duplication is accepted for tonight and is tracked as debt**: a future lane should extract `sealReauthGate` (and `authorizeSeal`'s shape) into a shared script (e.g. `/vac-seal-ceremony.js`) that financial-demo.html, tribunal-demo.html, and pharma-demo.html all load, instead of three independent copies.
- **(b)** State across the round trip is preserved exactly as financial-demo does it: an in-page `postMessage` from the same-origin `/auth.html` iframe, captured into `window.__vacVerified`, no query/hash/sessionStorage marker — because financial-demo's ceremony never navigates away from the page, there is no such marker to mirror. (Pharma-demo's old navigation-based approach, which *did* use a `localStorage` marker, is what's being replaced here, not what's being preserved.)
- **(c)** If `/v1/vat/authorize` fails (or is never reachable, e.g. the skip path with no session token), the receipt's "Action gate + audit" row shows the failure/refusal state and never claims `GATED & AUDITED`.
- **(d)** This lane cannot complete a live biometric capture headlessly. The check performed: confirm the live path reaches `/auth.html` inside the ceremony overlay (recorded URL below); run the skip path end-to-end headless against the live backend and confirm a receipt renders with a real token id (recorded below).
